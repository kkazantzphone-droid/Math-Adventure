# Domain boundary

Phase 1B implements pure core results/IDs, bounded exact math/DTOs, replay/canonical serialization, xoshiro128ss-v1, concept graphs and semantic puzzle/expression/geometry/quantity contracts. Phase 2 adds `families/`: bounded addition, inclusive quadrilateral classification and exact unit-length generators/validators, semantic hints and a static connected concept catalog. Existing value/replay identities and primitive behavior remain unchanged. No learner state, adaptation or game policy exists. Number Lab exposure remains structurally separate from assessment scopes, with no conversion or persistence. See [value rules](../../docs/DOMAIN_VALUE_MODEL.md), [replay rules](../../docs/DETERMINISTIC_REPLAY.md), historical [foundation evidence](../../docs/PHASE_1B_COMPLETION_REPORT.md) and current [family design](../../docs/PHASE_2_FAMILY_PROOF.md)/[report](../../docs/PHASE_2_COMPLETION_REPORT.md).

Domain modules may import only other domain modules through relative paths. They must not import UI, application, presentation, infrastructure, composition, shared browser utilities, external packages or platform APIs. `tsconfig.domain.json` omits DOM, Node and ambient framework types; lint also rejects imports leaving this folder, JSX, clock reads and production randomness. Positive and negative fixtures live under `tests/fixtures/architecture`, outside runtime source.

Phase 1C already supplies pure application contracts/integrity; Phase 1D supplies presentation/local-only speech infrastructure. Phase 2's stateless application facade exposes answer-free task views and delegates validation to these domain families through a deliberate developer UI path. The accepted scripted Phase 1V experience remains separate; no repository command, learner session or stored evidence is added by the family proof. See [the architecture](../../docs/ARCHITECTURE.md).
