# ADR-0003: Local-first learner persistence/privacy

Status: **ACCEPTED** · Date: 2026-10-04 · Phase: 0 (specification only)

## Context

Children's learner histories are sensitive. No accounts or externally transmitted learning telemetry are permitted in V1; local data can still be lost or exposed on a shared device.

## Decision

Persist separate minimal profiles/evidence locally behind a repository port, with IndexedDB the preferred browser candidate. No server/cloud learner store. Require revision/epoch-safe transactions, bounded retention, tested forward migrations, deletion and future local parent export/import contracts. Never claim encryption/backup automatically. Numeric retention, idb wrapper and final inactivity grace are proposals, not settled policy.

## Alternatives considered

Raw IndexedDB reduces dependencies but adds boilerplate; typed idb is provisional. localStorage is unsuitable for transactional histories. SQLite is a possible future native adapter. Cloud sync/database servers violate present requirements.

## Consequences

Parents own local control; no sibling evidence coupling. Storage errors must be visible, old schemas recoverable and imports validated. Real-data use waits for resolved retention/privacy decisions.

## Risks

Eviction/user clearing, shared-device/extension access, stale tabs, migration failure and exports surviving deletion. Local-first is not legal compliance.

## Reversal conditions

Revisit storage adapter for measured platform needs. External sync requires a distinct ADR/legal review/parent controls and cannot become default casually.
