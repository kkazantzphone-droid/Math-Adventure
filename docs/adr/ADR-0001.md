# ADR-0001: Client-side TypeScript/PWA runtime

Status: **ACCEPTED** · Date: 2026-10-04 · Phase: 0 (specification only)

## Context

An ordinary parent must run a child-focused offline-capable mathematics application without development tools, accounts or a managed server. This runtime constraint is authoritative in the user request.

## Decision

Design V1 as a client-side React + TypeScript PWA with local mathematical truth, adaptation and persistence. End users need no Python/Conda, Node/npm/pnpm, Git, Rust, Docker, shell or database server. No application backend. Optional future Python research/developer tools cannot become a runtime dependency silently. Tauri is the preferred future packaging candidate, evaluated separately.

## Alternatives considered

Vanilla/Preact/Svelte remain viable UI alternatives but no material requirement overturns React. Next.js can support static output but its server facilities are unnecessary. FastAPI/backend/cloud accounts introduce avoidable offline/privacy/operations burden. Immediate Electron/Tauri adds packaging before a measured need.

## Consequences

Static hosting is portable; dev/build tooling stays separate from parent installation. Browser storage, speech and install behavior remain capability-dependent. Pure domain/frontend reuse enables later native adapters.

## Risks

Browser eviction, varying local voices, host/update integrity and no server backup; no educational, legal or platform guarantees arise from architecture alone.

## Reversal conditions

Reconsider only when a documented material requirement cannot reasonably fit the client-side design. Backend/network or runtime-language changes require a new ADR and privacy/data analysis.
