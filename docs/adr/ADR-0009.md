# ADR-0009: Deterministic PRNG and replay mapping

Status: **ACCEPTED** · Date: 2026-10-05 · Phase: 1B

## Context

ADR-0004 accepted deterministic semantic replay but left RNG detail proposed. Phase 1B needs a small dependency-free pure transition, independently established vectors and bounded unbiased mapping before any actual family.

## Decision

Finalize `xoshiro128ss-v1` as the original authors' xoshiro128** 1.1 with four uint32 words, explicit ordered updates and unsigned modular arithmetic. A 32-character hexadecimal seed maps consecutive eight-character slices to s0–s3; accept either input case, emit lowercase and reject all-zero state. No automatic seed generation exists.

Use rejection sampling over unsigned output with an exclusive bound 1..2^32 and at most 128 draws; return consumed state on exhaustion. Preserve independent generator/content/semantic/canonicalization versions in `replay-v1`. `canonical-json-v1` has bounded data-only validation, sorted UTF-16 object keys and exact canonical-text parsing. Full rules are maintained in [deterministic replay](../DETERMINISTIC_REPLAY.md).

## Evidence and source terms

Source accessed **2026-10-05**: [Blackman/Vigna reference](https://prng.di.unimi.it/xoshiro128starstar.c). Its header dedicates rights to the public domain to the extent possible and grants unrestricted permission with a warranty disclaimer. It does not identify a specific CC0 instrument. Original project implementation follows the published algorithm; no source dump, jump functions or runtime dependency is added. Project code remains Apache-2.0; attribution/provenance remains beside the [independent fixture](../../tests/fixtures/golden/README.md).

The independently written BigInt model supplies three seeds with 16 output/state transitions each and nine bounded-choice cases. It uses arithmetic rotation and simultaneous state equations, with no production imports. A manually checked first step supplies another anchor. Local exact tests, unsigned-state properties and rejection/state-exhaustion cases establish this mapping. Statistical tests are not used as mathematical proof. Hosted Phase 1B execution remains future evidence after owner review.

## Alternatives and consequences

Implicit randomness, modulo-only mapping and app-version-only replay violate accepted requirements. A dependency/library or seed hash adds an unnecessary compatibility surface. Other established noncryptographic algorithms remain possible under their own immutable ID; none can reinterpret this ID. Cosmetic streams remain separate. This establishes reproducibility contracts, not puzzle content, security randomness or educational effectiveness.

## Reversal conditions

An independently demonstrated defect blocks release and requires a new behavioral ID where interpretation changes. Bounds/schema changes require explicit review and applicable new versions. Do not regenerate old evidence under a replacement algorithm.
