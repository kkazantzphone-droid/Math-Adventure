# ADR-0007: Offline/service-worker strategy

Status: **PROPOSED** · Date: 2026-10-04 · Phase: 0 (specification only)

## Context

Normal cached play must survive disconnection. Installation alone is insufficient; updates can mix shell/data versions or corrupt state if applied mid-session.

## Decision

Recommend complete release-namespaced essential caches, selected UI/instruction/number-speech plans, explicit offline readiness, a waiting worker and all-tab safe activation handshake before coordinated reload/migration. No unconditional skipWaiting while playing. Revisions/epochs and schema compatibility protect data. Tool choice provisionally vite-plugin-pwa/Workbox injectManifest, tested against simpler alternatives.

Chosen geometry/notation components and any fonts/rules must be self-hosted and included in their content-readiness manifests. SVG/MathML preference introduces no Phase0 package installation or online correctness dependency.

## Alternatives considered

Network gameplay or CDN essentials break offline/privacy. Blind auto-update may mix versions. generateSW/raw worker may be simpler but must satisfy the same tests. Provider-specific runtime APIs couple hosting unnecessarily.

## Consequences

Initial/optional downloads and reconnect update checks still use network. Rollback obeys schema compatibility; static origin migration needs parent local backup/import. Two retained compatible release sets are a quota-dependent proposal.

## Risks

Eviction/quota, incomplete downloads, blocking old tabs, service-worker compromise and offline users unable to receive fixes. No actual device/host proof yet.

## Reversal conditions

Revise worker/tool/hosting strategy after lifecycle tests; preserve cached normal gameplay and safe state. Desktop has a separate asset/update lifecycle. Backend is not the default solution.
