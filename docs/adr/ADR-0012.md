# ADR-0012: Prototype localisation and explicit local-only browser speech

Status: **ACCEPTED bounded implementation direction — PHASE 1D ENGINEERING PASS — BOUNDED CHECKPOINT 6 COMPLETE** · Date: 2026-10-05 · Phase: 1D

## Context and authority

The owner explicitly authorizes checkpoint 6 after complete verification and local preservation of owner-confirmed Phase 1V at `da72f532089186c83b48392ca6aa11264367f71e`. The current scripted number, shape and Explore content remains a visual prototype, without production puzzle families, learner evidence, persistence or adaptation. [ADR-0005](ADR-0005.md) already accepts exact locale identities, independent language settings, semantic speech plans and local-only speech. This ADR records the bounded implementation choices; it does not promote language packs or certify voices/accessibility.

## Decision

Keep the exact canonical architecture set **el-GR, en-GB, de-DE, fr-FR, es-ES, it-IT, pt-PT** in one typed locale boundary. Child-visible messages for el-GR/en-GB/de-DE implement the complete current-prototype schema, with version/schema metadata and **prototype-draft / native review pending** status. The remaining four manifests stay **planned/incomplete**, with no fabricated child translations. No locale is official; German does not inherit native review merely because schema checks pass.

Keep `uiLocale`, `instructionLocale` and `numberSpeechLocale` independently representable in query/bootstrap/session state. UI chrome/navigation uses uiLocale; task/hint/relationship instructions use instructionLocale; spoken number/math plans use numberSpeechLocale. Compatibility aliases `lang=el`, `lang=en`, `lang=de` set the prototype choices together, but canonical identities remain exact regional tags. Invalid or unavailable choices use explicit deterministic documented handling; navigator.language is not selection authority. No stored learner/preferences record is introduced.

Exactly one alias sets all three roles; absent/unknown/case-changed/repeated/malformed aliases default to el-GR. Optional `ui`, `instruction`, `speech` overrides accept one exact canonical tag from the seven-locale set. Absent overrides retain alias/default; invalid/repeated overrides reset only that field to el-GR. URLSearchParams decodes once. Requested planned locales remain canonical preferences, with effective Greek display plus `planned-pack` reason exposed to adults; planned speech remains unavailable. Effective content locales own document/part language, so fallback Greek is not mislabeled as a planned language.

Move wording into stable typed message IDs and typed arguments. Use structured literal/argument/plural/select data with native **Intl.PluralRules** and **Intl.NumberFormat**, bounded integer formatting without unnecessary grouping, and explicit missing-key/completeness handling. Render plain text through React; translations contain no HTML or executable code. A schema claimed complete must pass required-key checks, rather than conceal omissions behind fallback. Planned packs remain visibly planned even when their request resolves to a usable draft display pack.

Choose **zero new dependencies**. Structured messages satisfy this bounded plural/select requirement without a generic ICU parser or intl-messageformat. Exact mathematical fixtures/evaluation remain outside translation code; formatted/interpolated values do not establish correctness. Future richer ICU requirements must justify an exact dependency, license/install/transitive review and new evidence.

Construct typed, language-tagged fixed nonpersonal utterance plans from semantic concepts: instructions, number/shape prompts and hints, positive feedback, multiplication, square power and principal square root. Plans supply meaning rather than raw punctuation/glyph pronunciation. Bounded cardinal wording covers the current prototype values; arbitrary number spellout and unsupported planned-locale phrases remain future work. Principal √16 = 4 describes the nonnegative square root/side length and must not imply that x² = 16 has only one real solution.

The infrastructure browser adapter implements the existing Phase 1C speech port; composition wires it and the UI receives the port/capability boundary. Domain/application gain no browser speech globals, timers, randomness or platform imports. A voice is eligible only when exposed for the exact requested locale and **localService === true**. Explicit selection prevents implicit default, remote/cloud or region substitution: en-US does not satisfy en-GB and pt-BR does not satisfy pt-PT. Voice names are display labels, not unique identities.

Voice tag matching is case-insensitive for the exact canonical regional tag; it does not remove/substitute the region. Defensive deduplication uses URI, language, name and local flag together. The fixed draft catalog has fifteen plan kinds, including the required instruction/hint/feedback/relationships and bounded cardinal values 2, 3, 4, 5, 6 and 16; planned locales provide no phrase. Runtime validation rejects arbitrary text, extra fields and accessors, then copies immutable canonical plan data before adapter use.

Enumerate immediately, tolerate an initially empty list, subscribe to voiceschanged, bound loading/retry and allow a later explicit refresh. Defaults are a **1,500ms loading bound, 150ms retry interval and 10,000ms playback watchdog**, configurable/test-injected. Capability handling uses unknown internally, then loading/missing/ready-local/error; the existing port's tested-offline state is never emitted by this adapter. Playback outcomes preserve completed/cancelled/unavailable/error/timeout. Cancel/replace obsolete speech on navigation, badge/context changes, locale changes, mute/disable and replay; ignore stale end/error events and cancel on provider change/disposal. Never accumulate an indefinite queue. Speech failure cannot alter scripted outcomes or navigation.

Speech remains **explicit and optional, with no autoplay**. Child replay uses only a useful current fixed plan and is available only when the corresponding exact local capability is ready. Full visual interaction remains available when speech is missing. Avoid duplicate aria-live/TTS delivery or automatic competition with screen readers. A deliberate developer/adult diagnostic query exposes requested-locale status and fixed synthetic phrase tests, without becoming required child navigation. No arbitrary entered text, learner names/answers/history, microphone, speech recognition, telemetry, remote service or persistent device fingerprint is included.

**Reported local is separate from tested offline.** localService cannot create a tested-offline claim; this adapter and diagnostics make no tested-offline assertion. Any future explicit disconnected-device observation must be scoped to the exact voice/locale/provider/device/browser surface, with session-only evidence and invalidation rather than a stale guarantee. Unit/fake tests may represent the port state but cannot establish real playback, pronunciation, privacy or offline operation.

## Alternatives and consequences

Retaining ad hoc two-language branches cannot supply the required typed schema, German prototype copy or independent preferences. A general localisation framework/ICU parser adds unnecessary parser/dependency surface for fixed structured messages. Browser language negotiation would confuse available prototype packs with reviewed support. Default/remote/regional voice fallback would violate the accepted policy, even when it makes a missing-voice demonstration appear successful.

The exact locales and manifests provide an extension seam without fabricating seven-language completeness. Optional child-controlled speech improves access to fixed prototype wording only where a device exposes a suitable voice. Missing exact voices are a valid capability result, not a reason to weaken the policy. Native wording review, actual-device/screen-reader checks and offline pronunciation/provider proof remain independent gates. No PWA/offline shell, durable preference, learner profile, evidence, adaptation or production validator is implemented here.

## Reversal conditions

New locale data or a speech provider must preserve exact identities, independent preferences, semantic plans and the existing port. Any remote/default/region policy change, arbitrary user speech or durable learner/preferences storage requires separate owner authority and privacy/architecture review. Preserve historical Phase 1V evidence and independent mathematical/application integrity; reverse only this stage's own candidate changes when a gate cannot be satisfied.
