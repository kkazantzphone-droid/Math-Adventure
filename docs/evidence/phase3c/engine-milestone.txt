## Implemented containment and playable behavior

`vite.slice.config.ts` builds a deliberate developer entry at
`tests/browser/phase3c/`, with compile-time synthetic capability and runtime
requirements for `http://127.0.0.1` plus an explicit port. The normal product
composition neither imports the loop/database nor silently creates a learner
store. The developer entry has only two fixed synthetic profiles; there is
no nickname/name field, arbitrary learner import, account, telemetry or cloud
storage. IndexedDB opens only after an explicit fixed-profile/storage choice.

The Space visual baseline presents all eight bounded families: existing addition,
inclusive quadrilateral classification and exact unit length, followed by numeral
recognition, counting, comparison, nonnegative subtraction and missing number.
Each task is deterministic; application regenerates its immutable replay and
delegates structured-answer correctness to domain. UI owns native controls,
semantic presentation, help and feedback. New generator/content IDs retain old
replay behavior. Semantic hints do not create answer truth.

The loop supports profile/activity choice, correct and incorrect answers, retry,
progressive mathematical help, optional explicit speech, skip, stop and explicit
resume. Session ordinals advance on session transitions rather than refresh.
Profile switching fences obsolete callbacks, cancels speech and clears transient
exploration; database epoch/revision checks remain the authority for writes.
There is no sibling ranking, lives, timed access, streak pressure or forced
completion.

Manual activity persists permitted preferences/session/progress without adding
observations or recommendations. Fresh manual profiles have empty events and null
recommendation; earlier explicitly collected synthetic-policy evidence is preserved
when mode changes, with no retrospective credit from manual activity. Explicit
synthetic proposed-policy mode uses
the unchanged `phase3b-synthetic-policy-v1` engine and existing three-family
evidence catalog. Reasons remain available for developer inspection. The five
new families return `limitedEvidence`; no new attainability claim or mastery is
manufactured. Exploration and Number Lab remain session-only and outside stored
assessment evidence. Accessible quantity descriptions cannot earn visual
numeral/counting credit. Mathematical hints affect classification; neutral
accessibility support does not become mathematical help.

## Atomic state, recovery and update boundary

`phase3c-synthetic-loop-v1` is an exact bounded developer aggregate, capped at
64 observation/checkpoint events. The cap is engineering capacity, not accepted
retention policy. It stores scoped observations plus validated minimal derived
state, session/preferences/progress and recommendation metadata. It reconstructs
the unchanged candidate adaptation engine and checks derived state for equality. Capacity exhaustion refuses new events or
writes; it never prunes retryable receipts or silently drops evidence. The fixed
runtime receipt capacity is 256, separate from the 64-event aggregate bound.
It stores no completed raw answer history. The durable pending journal carries a
validated prepared verdict and minimal observation, rather than submitted raw
answers/tasks. Success receipts contain no raw submitted answer or replay.

An eligible answer regenerates domain truth, prepares one logical classification,
stages its bounded pending state, then atomically commits final observation,
derived state, recommendation, progress and success receipt through Phase 3A.
Saved feedback follows transaction completion. Exact retry checks epoch before
receipt deduplication/revision and cannot duplicate evidence. Reload reconciles a
pending command against epoch, revision and exact receipt before an explicit retry;
it does not silently replay unsaved work. Quota/abort/denial and uncertain state
retain truthful unsaved/read-only feedback.

Deletion advances the global fence. A stale surviving pending record remains
read-only for inspection and explicit deletion; it cannot resume a command across
that fence. No conflict path auto-upserts, resets or erases a record. Full fixed
namespace rows and receipts are validated during database recovery. Future or
unknown layouts preserve data and offer explicit recovery/unsaved choice.

The existing offline controller accepts an optional learner-data lifecycle port;
normal composition has no database import. Synthetic runtime generation leases
fence/drain all commands and selections, including initial worker controller
acquisition. Any fixed profile's pending record, in-flight work, unresolved state
or unsaved client blocks readiness. Before activation it validates epoch,
rows/receipts and the target worker's verified cached
`phase3c-learner-reader-v1` declaration for layout `2` and this record codec.
Shell schema `1` alone is insufficient. Controller recovery reopens and validates
known compatible storage before interaction/acknowledgement; incompatibility
preserves recovery or explicit unsaved play. Cached shell readiness and learner
saved-state feedback remain separate.
