## Harness boundary and reproduction

The review model is [tests/fakes/synthetic-adaptation-review.ts](../tests/fakes/synthetic-adaptation-review.ts),
with [scenario assertions](../tests/unit/adaptation-review.test.ts). Both are
outside `src/`, absent from application composition and checked by the existing
tool/test project. No dependency, lockfile, production storage, learner codec,
application/domain behavior or child UI is added. Existing exact, injected
`xoshiro128ss-v1` supplies only deterministic selection among canonical ties.
Explicit coarse days, session ordinals, catalog availability and seeds supply
all scheduling/selection inputs; there is no clock or hidden randomness.

Only labels beginning `SYNTHETIC-` and completion fixtures with literal
`synthetic: true` are accepted. All fixtures are authored scenarios, with no
real person, answer log, time-to-answer, age, sibling relation or telemetry.
The in-memory `audit` allows assertions about frozen exclusions and exact
retries. It is **review instrumentation**, not a persistent history proposal,
receipt lifecycle or bounded production state implementation. The model trusts
typed, family-declared semantic fingerprints; it does not establish a safe
production codec for hostile inputs or approve meaningful variation definitions.

Use the exact Node 24.21.0 / Corepack-managed pnpm 12.9.1 and repository-local
cache settings from [development](DEVELOPMENT.md):


The source also retains attained Emerging/Developing accomplishments when recent
evidence becomes sparse. This is an **explicit simulation interpretation**: the
prose specifically protects Secure, and does not fully define persistence of
earlier attainment states. Phase 3B must separate current recommendation readiness
from past attainment. A retained Developing summary with an empty recent window
must not justify a claim of present readiness; define familiar/probe/exploration
recovery for limited evidence instead of silently adopting this interpretation.

Finite evidence counts must be semantic, not parameter-tuple counts. For example,
quadrilateral `maximum: 1` has only width/height 1 and two shears before
transformations. Its many rotations/scales/orderings cannot be assumed to supply
five meaningful evidence cases; Phase 3B must enumerate an educator-reviewed
evidence universe and attainable coverage trace for **each offered bound**.
The Phase 2 1,152 maximum-spec transformed tuples are not proof of 1,152 distinct
assessment items. The same requirement applies to unit-length `maximum: 1`
and any very small numeral/counting universe.

The numeric proposals remain five/three Developing, ten/eight Secure,
two-day/twice retrieval, three varied support recoveries, revisit +2/+7/+21/+30,
three consecutive scored tasks, ten/500/60-day evidence limits. Passing a trace
does not validate those numbers. Proposed retention duration, default adaptation,
manual/parent controls, inactivity/grace behavior, legal/profiling assessment and
consented trials remain human decisions in the
[Phase 3 implementation plan](PHASE_3_IMPLEMENTATION_PLAN.md). No real-child
policy is shipped by this task.
